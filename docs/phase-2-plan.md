# 第二期需求与实施清单

状态：待实施方案。2026-09-09 根据本次讨论和本机 ZCode 验证整理。

## 1. 目标与范围

让用户将内容投递到指定电脑的 AI 应用，并通过录制好的固定流程完成输入、选项选择和可选提交。日常回放不调用大模型，不依赖 Codex Computer Use；Computer Use 仅用于开发期验证。

- 平台目标：Windows、macOS、Linux，整机内存至少 16 GB；不是为模型预留 16 GB。
- 首个验收对象：Windows ZCode，先本机独立测试项目，再小米电脑。
- 核心输入：本次投递的文本；图片、文件先完善下载，再单独适配附件上传。
- 优先支持普通点击、双击、常用快捷键、文本输入、下拉选择。
- 暂不支持复杂拖拽、验证码、登录代操作、自绘画布、跨应用长链路、全局自主规划。
- 应用关闭时自动启动、自动新建或切换复杂会话放后续；第一版要求应用已打开且目标会话明确。
- 不承诺同一流程不经验证即可跨平台复用；流程语义共用，定位配置按平台和应用版本适配。

## 3. 用户操作流程

### 3.1 入口与新建

时间线增加“自动化”页：流程名称、目标应用、最近验证结果、运行、编辑、重新录制。托盘提供已保存流程的快捷入口。

新建只需填写名称并选择正在运行的目标窗口。默认输入为“本次投递的内容”，默认终点为“填入后等待确认”。同名多窗口必须让用户明确选定项目或会话，不直接取第一个。

### 3.2 录制悬浮条

显示目标应用、录制状态、步骤数，以及暂停、标记下一目标但不执行、结束按钮。

1. 点击开始后才监听输入；目标之外的操作不录入。
2. 切出目标应用自动暂停，返回后提示恢复；原生文件选择框需验证属于目标应用后纳入。
3. 记录按下、释放、时间和目标上下文，合并成单击、双击、组合键等动作。
4. 鼠标移动不形成步骤；短时保留目标窗口画面和控件快照，处理点击后菜单消失的问题。
5. 输入监听回调只入队，识别异步完成；不得在系统输入钩子里同步运行 OCR。
6. 排除悬浮条自身及执行器注入的事件，避免自录循环。
7. 用户点“标记下一目标”后只采集目标，不触发操作。若拦截点击不能可靠实现，改为框选，不能冒险点击发送。

### 3.3 步骤检查

每步展示动作、目标、内容来源、定位方式、预期结果。支持修改、停用、删除、重新点选、仅高亮定位、逐步试运行。

| 录制操作 | 生成步骤 | 默认处理 |
| --- | --- | --- |
| 点击需求框 | 聚焦输入框 | 检查目标窗口和可编辑状态 |
| 粘贴示例需求 | 粘贴输入变量 | 不保存录制时的真实剪贴板内容 |
| 连续键入文字 | 合并输入 | 提示使用变量；明确选择后才保存常量 |
| 复制当前选区 | 复制到运行内变量 | 回放时取值，不保存录制时的文字 |
| 下拉选择 | 展开、等待、选中、验证 | 保存选项文字与作用区域，不保存“第三项” |
| 快捷键 | 组合键动作 | 必须绑定目标窗口，避免全局误执行 |
| 点击发送 | 提交动作 | 默认停用；明确启用后才进入提交流程 |

已有草稿默认暂停。覆盖草稿、追加内容必须是显式配置，不以 Ctrl+A 默认清空用户文本。

### 3.4 运行

用户选择条目、目标电脑、流程，预览内容和终点，再执行。发送前预览固定到本次任务，后续系统剪贴板变化不能更换任务内容。

状态分别为已接收、等待桌面、定位中、填入完成、等待确认、提交中、已确认接收、失败、取消。ZCode 生成任务的业务完成不包含在第二期投递成功内。

## 4. 本地执行与定位

保持 Rust workspace；新增独立自动化库和运行在交互式用户会话内的本地执行器。核心负责投递、持久化和回执；桌面执行器负责定位与输入。不要把所有平台控制代码塞进托盘 main.rs。

### 定位顺序

1. 应用有受支持接口时优先使用，但必须能作用于指定会话。
2. 可连接的网页采用 DOM；Windows 普通应用采用辅助功能控件。
3. 结构不可用时采用局部 OCR，完整文字匹配并限定区域。
4. 无文字图标采用局部模板匹配，保存缩放、主题等适用条件。
5. 第一版匹配失败即暂停，不自动启用付费视觉模型“猜着操作”。

每个定位条件包含应用身份、窗口约束、区域或锚点、控件角色/名称、备选文字或图像。临时元素索引、运行时生成 ID、绝对坐标不作为持久化主键。

“高”不得部分匹配到“最高”；重复“发送”需限定输入区。匹配阈值和第一、第二候选差距由实测校准，置信度不是成功概率。

截图像素、窗口坐标、屏幕物理坐标和 DPI 缩放必须显式转换。窗口移动或菜单展开后重新定位；屏幕捕获失败、最小化、遮挡影响识别时先恢复可操作状态或暂停。

动作优先使用控件 Invoke/Selection 等语义操作，支持时减少依赖前台焦点；否则执行目标点击或快捷键，并以新状态验证，不能根据 API 返回成功就判定业务成功。

### 等待、重试与桌面互斥

- 每台桌面同一时间只允许一个输入流程；网络接收可并发。
- 等待控件出现、可用、选项显示及结果变化，不重放人工停顿。
- 定位读取可有限重试；粘贴前先判断是否已填入，避免重复追加。
- 提交前持久化“即将提交”状态。提交超时或进程中断后进入结果不明，先核对会话，不盲目重发。
- 按钮需要明确成功断言；找不到、多个匹配、弹窗、用户操作冲突均暂停。
- 暂停、取消、紧急停止须在下一输入动作前生效；已经送达的提交不能声称已撤销。
- 锁屏、断开远程桌面、权限级别不匹配分别报告；不自动提权。

### 剪贴板

写入本次任务内容后，通过受控粘贴和内容回读验证。临时内容仅驻留内存。

恢复原剪贴板前核对序列号和本次写入标记，用户期间复制了新内容则不覆盖。多格式备份无法可靠完成时提示限制，不能用纯文本备份宣称完整恢复图片和文件剪贴板。

## 5. 数据与网络边界

流程定义包含版本、名称、平台、目标应用约束、输入变量、步骤、定位条件、超时、成功断言和提交策略。流程修改后产生新版本，运行固定引用该版本。

运行记录包含任务去重标识、发送设备、接收设备、流程版本、状态、当前步骤、错误类别和时间。默认不记需求正文、完整屏幕或原剪贴板。

网络仅接受接收端已登记的流程名称和有类型的输入，不接受任意脚本、命令路径或截图识别后生成的任意执行代码。内容按数据处理。

接收端单独授权设备与流程；不能因为同在 tailnet 或已允许应用启动就默认允许桌面输入。网页调试入口仅本机使用，不直接暴露给远端。

任务重复投递返回原运行状态。设备离线、版本不存在、未授权、桌面忙碌分别返回明确结果。崩溃恢复必须区分执行前、填入后、提交结果不明。

## 6. 传输体验补齐

文件和图片提供“复制到剪贴板”“仅下载”“下载并打开”“打开所在文件夹”。默认目录已有配置，直接复用。

- 下载与剪贴板应用拆开，避免仅下载也覆盖剪贴板。
- 流式写临时文件，校验完整性后完成原子落盘；同名默认生成新名称，不静默覆盖。
- 显示进度、取消、失败原因和重试；断点续传另立验收项，不默认承诺。
- 完成后才调用系统默认打开方式；可执行程序和脚本默认不自动打开。
- 多文件批次默认打开目录，不同时启动大量应用。
- 源文件移动、源机离线、持有元数据但没有实际内容需分别提示。

## 7. 可直接执行的工作包

按顺序推进。每包提交可审查的代码差异及 PASS / FAIL / BLOCKED 证据；没有设备的项目标 BLOCKED。

| 工作包 | 内容与建议归属 | 验收与依赖 |
| --- | --- | --- |
| P0 传输复现 | core/client、engine、clipboard；建立两机样本与失败阶段记录 | 文本、图片、文件、目录逐项对比；取得真实失败证据，不先猜原因 |
| P1 本地固定流程原型 | 新增自动化库和开发用执行器；先不接网络和录制 UI | 自动定位 ZCode 输入框、粘贴、回读、展开菜单、改变选项后恢复；实际提交单独测试 |
| P2 OCR/图像可行性 | 自动化库内识别适配器 | 在真实局部截图上验证中文、重复文字、相似图标；输出耗时、峰值内存、误匹配案例 |
| P3 录制器 | 输入事件采集、目标捕获、悬浮条 | 只记目标应用；快捷键合并正确；标记发送不触发；注入事件不被重新录入；依赖 P1 |
| P4 流程编辑与回放 | 时间线自动化页、流程存储与验证器 | 可查看、重选、停用步骤；重启后可载入；失败停在准确步骤；依赖 P2/P3 |
| P5 文件操作分离 | core 传输接口、CLI、托盘、timeline | 仅下载不改剪贴板；成功后打开；取消不留伪完整文件；目录设置生效 |
| P6 跨机投递 | core protocol/server/client、运行记录 | 去重、授权、桌面互斥、离线提示、崩溃恢复；在小米 Windows ZCode 验收；依赖 P4 |
| P7 平台与应用扩展 | macOS/Linux 执行器、兼容矩阵 | 每个平台每个应用单独验证；优先明确的主流目标，不预报兼容率 |

P1 是首个停止评估点：如果连 ZCode 本机自动聚焦和回读都不稳定，先修执行方式，不提前开发完整录制界面。

## 8. 验收矩阵与资源预算

以下为拟定工程门槛，不是已测结果：

- Windows ZCode 固定窗口下连续 20 次输入与下拉流程，要求 20 次内容正确、零误发；保留每次结果。
- 窗口移动、100%/125%/150% 缩放、深浅主题、已有草稿、多窗口、用户抢占、锁屏分别验证；不支持的条件明确阻止运行。
- 发送流程在独立测试项目中验证：准确接收一次；超时/重复请求不产生二次提交。
- 本机和跨机验收分开；Computer Use 成功不能替代独立执行器验收。
- 在 16 GB 整机、目标 AI 应用同时运行的环境测量。记录空闲占用、识别峰值、CPU 和端到端延迟。
- 初始优化目标：执行器与识别模块合计增量内存不超过 1 GB，局部定位 P95 不超过 1 秒；不含目标应用和首次加载，后续根据基准调整。
- OCR 按需加载，按步骤识别局部窗口，不常驻全屏高频推理；默认无云端调用，离线可回放已配置流程。

## 9. 实施建议

下一步只做 P1：可手工定义的小流程原型，先证明不靠大模型能重复执行。随后选择轻量 OCR/模板实现，再做录制器，最后接跨机投递。总体保持模块化单体，不引入分布式调度平台或全局自主 Agent。

已有托盘图标改动、AGENTS.md 和用户其他改动均不属于本方案实现，不应一并覆盖或提交。
