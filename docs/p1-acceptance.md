# P1 验收记录

## Computer Use 补充复测

用户要求使用 Computer Use 重测，使用 `@oai/sky` 在本机 ZCode 的 `zcode-input-test` 项目完成以下操作；本节不改变原生执行器的验收状态。

| 操作 | 实际结果 |
| --- | --- |
| 恢复窗口、进入测试项目 | 原窗口最小化，激活后通过项目旁的新建任务按钮进入测试草稿页 |
| 点击输入框、追加中英文数字 | ` CU复测456` 出现在输入框；截图与控件文本一致 |
| Ctrl+Z 撤销追加 | 恢复为原来的单份测试草稿 |
| 下拉选择变化 | `最高` → `高` → `最高`，每次均确认显示值变化与菜单关闭 |
| Ctrl+A / Ctrl+C / Right / Ctrl+V | 选中已知测试文本并复制，末尾粘贴后出现两份相同文本 |
| Ctrl+Z 撤销粘贴 | 恢复原草稿；未点击发送、未提交任务 |

观察到的实现问题：

- Computer Use 的 `focused_element` 仍显示 `RootWebArea`，但截图中的光标、选中文本与实际输入证明编辑区获得输入。该字段不能单独作为此工具的聚焦判断依据，也不能据此推断原生 UIA CompareElements 的行为。
- 点击后立即读取的控件树和截图可能尚未完成更新；再次观察后才得到新状态。正式流程应等待预期状态，避免因第一次快照未变化就重复点击。
- 下拉框的“低”和“高”选项没有可访问名称，本次“高”使用当前截图定位；“最高”有名称并通过控件索引点击。索引会变化，不能作为录制后的稳定定位条件。
- 本轮使用真实 Ctrl+C/Ctrl+V 验证粘贴，系统剪贴板现为测试文本，未恢复测试前剪贴板内容。草稿及下拉设置已恢复；ZCode 留在测试项目页面。
- 本轮没有运行 Rust 原生执行器，也没有验证发送、跨机投递或连续 20 次回放。

本记录区分离线测试、原生实现与真实应用验收。Computer Use 的历史操作结果不作为本地执行器的通过证据。

## 真实应用测试步骤

1. 在独立测试项目中运行只读探测，记录实际 exe/title 和输入框、下拉框的定位条件。
2. 确认测试输入框为空；有已有草稿时必须拒绝，不自动清空。
3. 使用显式执行开关进行自动聚焦与测试文字填入；回读完全一致才判定输入通过。接口返回成功不等于回读通过。
4. 单独验证菜单展开和选项变化，再恢复原选项。没有可靠控件名称或 Selection pattern 时记录不支持，不按坐标猜测。
5. 测试用户抢占焦点、目标关闭、选择器多匹配；必须中止后续输入。
6. 提交动作不纳入本轮。只有原生流程验证通过后，才继续接录制入口与跨机投递。

超时和停止不代表能撤销已经发生的界面动作。同步 UIA 调用期间的中断能力必须单独说明和验证。
